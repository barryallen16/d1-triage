Within-rule discrimination

          

            Can the model separate vulnerable functions from fixed ones when both match the same Semgrep rule? Static scanner rules score 0.5000 (random coin flip) because they fire on both. Contrastive LoRA v2 reaches 0.6027 L3 within-rule AUC by checking guards in the code.
          

        


        

          
Verified security patches

          

            Location-proxy labels (L0) count any alert in a modified file or method, mixing tests and refactoring noise into true positives. Verified patch labels (L3) require the alert line to sit inside the security fix diff and match the advisory CVE CWE.
          

        


        

          
Vul4J census check

          

            Evaluated across 126 Java repositories (14 Semgrep alerts: 5 TP, 9 FP across 10 CVEs). Zero-shot d1-3B scores 0.8000 AUC, while Contrastive LoRA v2 scores 0.5222 because the 465 training commits lack crypto and SSL rules.

How d1-triage evaluates alerts

        

          Grounding the flagged line and fine-tuning on full enclosing methods makes the model read the guards around the sink.
        

      


      

        

          

            
          

          
Statement sink anchoring

          

            d1_triage/sink_finder.py locates the flagged sink statement (new File, dbf.setFeature) and adds >>> [ALERT LINE], lifting L0 within-rule AUC from 0.4297 to 0.5986.
          

        


        

          

            
          

          
Full-method contrastive LoRA

          

            Trained with direct 2-class logit loss and KL anchoring on 1,643 non-test Java methods from 465 held-out commits, with zero overlap against the 68 GHSA evaluation advisories.
          

        


        

          

            
          

          
Rule-swap control

          

            Swap deltas stay positive across all four levels (+0.0365 on L0 to +0.0724 on L3 for LoRA v2), showing sensitivity to guards in the method body.
